# Contributing

This repository holds release notes and the public record of what ships. There is no application source here, so there is nothing to build.

## What is welcome

**Corrections.** If a release note says the app does something it does not do, that is a real bug in the documentation and worth an issue. Include the version you are on and what you saw instead.

**Typos, broken links, unclear sentences.** Open a pull request directly.

**Questions about a release.** Start a discussion rather than an issue, so the answer stays findable for the next person.

## What is not welcome

- Security reports. Do not open a public issue for a vulnerability. Email corey@wynfall.dev instead, and we will credit you if you want.
- Requests to open source the application, the model, or the training pipeline. The answer is no, permanently, and stating it here saves everyone a thread.
- Feature requests framed as demands. Feature requests as a discussion post are fine and are read.

## How a change lands

1. Fork and edit on a branch.
2. Keep the voice: plain words, short sentences, past tense for what shipped, present tense for what it does.
3. Match the existing entry format. Version heading, a bold lead line when the release has a theme, then bullets.
4. Open the pull request against `main`, one release or one fix at a time.

A documentation pull request is usually merged within a day. If a note needs a fact only we have, we will correct it ourselves and credit you in the thread.
